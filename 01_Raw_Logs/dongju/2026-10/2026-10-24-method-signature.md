## 배운 개념

### 1. 시그니처 = 메서드 이름 + 매개변수 타입 목록(개수·순서)

```java
int sum(int a, int b) { ... }      // 이미 있음

long sum(int a, int b)   { ... }   // (가) ❌ 반환 타입만 다름 → 같은 시그니처
int  sum(int x, int y)   { ... }   // (나) ❌ 매개변수 이름만 다름 → 같은 시그니처
int  sum(long a, int b)  { ... }   // (다) ⭕ 타입이 다름
int  sum(int a, long b)  { ... }   // (라) ⭕ 순서가 다름
```

| 바꾼 것 | 시그니처에 포함? |
|---|---|
| 매개변수 타입·개수·순서 | ⭕ → 오버로딩 가능 |
| 반환 타입 | ❌ |
| 매개변수 이름 | ❌ (컴파일러에겐 `sum(int, int)` 일 뿐) |
| 접근 제어자, `throws` | ❌ |

### 2. 왜 반환 타입은 빠지나 — 호출부에서 볼 수 있는 정보

```java
sum(1, 2);   // 결과를 변수에 담지 않고 그냥 호출 — 합법
```

- 컴파일러는 각 메서드의 반환 타입을 **알고 있다**(선언에 적혀 있음).
- 모르는 건 **호출하는 쪽이 어느 것을 원하는지**. 호출하는 줄에서 보이는 건 **이름과 인자뿐**이고, 결과를 버리는 호출도 합법이라 반환 타입으로 고를 단서가 없다.
- 그래서 고르는 기준이 될 수 있는 **이름 + 매개변수 타입**만 시그니처가 된다.
- 오버로딩은 이 시그니처를 보고 **컴파일할 때** 호출 대상을 정한다(정적 바인딩: [[overriding-vs-overloading-binding]]).

### 면접 답변

> "메서드 시그니처는 메서드 이름과 매개변수의 타입·개수·순서로 구성되고, 반환 타입이나 매개변수 이름은 포함되지 않습니다. 호출하는 코드에서는 이름과 넘기는 인자만 보이고 반환값은 버릴 수도 있어서, 컴파일러가 반환 타입으로는 어느 메서드를 부를지 고를 수 없기 때문입니다."

## 오답·헷갈린 점

- 👍 (가) ❌ (나) ❌ (다) ⭕ (라) ⭕ — 네 개 모두 정답. "이름 + 매개변수 타입 목록" 빈칸은 보충.
- **전**: 반환 타입 오버로딩이 막히는 이유 = "컴파일러 입장에선 **반환 타입이 어떤 것인지 컴파일 과정에서 알 수 없기 때문**" → **후**: 컴파일러는 반환 타입을 **안다**. 모르는 건 **호출부가 어느 것을 원하는지**(호출부엔 이름과 인자뿐, 결과 버리기도 합법).

## Q&A

**Q. 메서드 시그니처는 무엇으로 구성되나?**
A. 메서드 이름 + 매개변수 타입 목록(개수·순서). 반환 타입, 매개변수 이름, 접근 제어자, throws 는 아니다.

**Q. 반환 타입만 다르게 오버로딩할 수 없는 이유는?**
A. 호출부(`sum(1, 2);`)에는 이름과 인자만 보이고 결과를 버릴 수도 있어 컴파일러가 고를 단서가 없다.
