## 배운 개념

### 1. "컴파일 언어 / 인터프리터 언어"는 구현의 성질이다

- 같은 자바 코드라도 HotSpot JVM 에서는 인터프리터 + JIT 으로, GraalVM Native Image 에서는 실행 전에 통째로 기계어로(AOT) 실행된다.
- → 언어에 "컴파일 언어 / 인터프리터 언어" 딱지를 붙이는 건 부정확하다. 물어야 할 건 **"이 언어가 어떤 방식으로 실행되는가"**.

### 2. Hello.java 가 CPU 에서 돌기까지의 변환

| 변환 | 누가 | 언제 |
|---|---|---|
| 소스(`Hello.java`) → 바이트코드(`Hello.class`) | `javac` — **JDK 의 개발 도구, JVM 바깥** | 실행 **전** (개발 PC / CI) |
| 바이트코드 → 기계어 | ① **인터프리터** (한 줄씩 해석, 결과 버림) ② **JIT** (핫스팟만 컴파일해 코드 캐시에 저장) | 실행 **중** (JVM 안) |

- JVM 안에도 컴파일러가 있다 → **JIT**. 단, JIT 이 바꾸는 건 소스가 아니라 **바이트코드 → 기계어**.
- 운영 서버의 JRE 에는 `javac` 가 아예 없다 (JDK ⊃ JRE ⊃ JVM).

### 3. 결론

> 자바는 **하이브리드**다. 실행 전에 한 번 컴파일(javac)하고, 실행 중에 해석(인터프리터)과 JIT 컴파일을 섞어 쓴다. 섞는 주체가 JVM.

### 면접 답변

> "컴파일 언어냐 인터프리터 언어냐는 사실 언어가 아니라 실행 방식의 성질인데, 자바는 둘을 섞은 하이브리드입니다. 실행 전에 javac 가 소스를 바이트코드로 컴파일하고, 실행 중에는 JVM 이 바이트코드를 인터프리터로 해석하다가 자주 실행되는 핫스팟만 JIT 으로 기계어 컴파일해서 캐싱합니다."

## 오답·헷갈린 점

- **전**: "자바는 인터프리터 언어다" + "그 언어를 실행하는 방식이다" → 두 문장이 모순. **후**: 실행 방식의 성질이라면 언어에 단정할 수 없다. 자바의 실행 방식은 **하이브리드**.
- **전**: "자바는 컴파일러 방식으로 실행한다" (반대 극단) → **후**: 실행 전 컴파일 + 실행 중 해석·JIT.
- **전**: "**JVM 의 컴파일러**가 소스 코드를 바이트코드로 변경한다" → **후**: 그건 `javac`(JDK 도구, JVM 밖, 실행 전). JVM 안의 컴파일러는 JIT(바이트코드 → 기계어, 실행 중). ⚠️ 같은 날 오후 인터뷰([[2026-10-22-jdk-jre-jvm-wora]])에서 정정한 "JVM 이 자바 프로그램을 컴파일한다"가 **두 번째로 재발**. javac 와 JIT 을 "어느 상자에 있나(JDK vs JVM) / 언제(실행 전 vs 중) / 무엇을 무엇으로" 세 축으로 구분할 것.
- **전**: "hello.class 를 바이트코드로 컴파일한다" → **후**: 입력은 `Hello.java`, 출력이 `Hello.class`.
- **전**: "바이트코드를 기계어로 번역은 잘 모르겠다" → **후**: 오후 인터뷰에서 직접 답한 인터프리터 + JIT. 힌트("인○○○○", "J○○")로 바로 복원됨 → 아는데 **두 경로를 한 그림으로 연결하지 못한** 상태였음.

## Q&A

**Q. 자바는 컴파일 언어인가, 인터프리터 언어인가?**
A. 둘 다 아닌 하이브리드. 그 구분 자체가 언어가 아니라 실행 방식의 성질이다.

**Q. 소스 → 바이트코드, 바이트코드 → 기계어는 각각 누가 언제 하나?**
A. 소스 → 바이트코드는 javac(JDK 도구)가 실행 전에. 바이트코드 → 기계어는 JVM 이 실행 중에, 인터프리터(해석) 또는 JIT(핫스팟 컴파일·캐싱)으로.

**Q. JVM 안에 컴파일러가 있나?**
A. 있다, JIT. 하지만 javac 와 달리 바이트코드를 기계어로 바꾼다.
