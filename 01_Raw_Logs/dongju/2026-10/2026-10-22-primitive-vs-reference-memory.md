## 배운 개념

### 1. 차이는 "변수 안에 무엇이 들어 있나"

| | 변수 안에 들어 있는 것 | null 가능 | 기본값 (필드만) |
|---|---|---|---|
| 기본형 8개: `byte` `short` `int` `long` `float` `double` `char` `boolean` | **값 자체** (`int count = 3` → 4바이트 칸에 3의 비트 패턴) | ❌ | 0 / 0L / 0.0 / false / `'\u0000'` |
| 참조형 (클래스, 배열, 인터페이스, enum …) | 힙 객체를 가리키는 **참조** | ⭕ | null |

- 기본형 변수는 "어딘가 미리 만들어 둔 3"을 가리키지 않는다. 미리 만든 객체 재사용은 `Integer.valueOf` 캐시(-128~127) — **참조형 `Integer`** 의 이야기다 ([[wrapper-cache-autoboxing]]).

### 2. 기본값은 필드만 받는다

```java
void test() {
    int x;
    System.out.println(x);   // 컴파일 에러: variable x might not have been initialized
}
```

- 지역변수는 기본값이 없다. 컴파일러가 "값을 넣기 전에 읽는 코드"를 막는다(definite assignment).
- 기본값(0/0L/false/null)은 **static 필드**(클래스 로딩 준비 단계)와 **인스턴스 필드**(`new` 시)만 받는다.

### 3. 메모리 위치 — 그릇을 따라간다

```java
class Member {
    int age;
    String name;
}

void join() {
    int count = 3;
    Member m = new Member();
    m.age = 20;
    m.name = "DJ";
}
```

| 대상 | 위치 | 들어 있는 것 |
|---|---|---|
| `count` | 스택 (지역변수) | 값 3 |
| `m` | 스택 (지역변수) | `Member` 객체를 가리키는 참조 |
| `Member` 객체 | 힙 | `age` 칸, `name` 칸 |
| `age` | **힙** (객체 안의 필드) | 값 20 |
| `name` | 힙 (객체 안의 필드) | `"DJ"` String 객체를 가리키는 참조 |
| `"DJ"` | 힙 (문자열 상수 풀, Java 7부터 힙 안) | 글자 데이터 |

> "기본형은 스택에 있다"는 **틀린 일반화**. 기본형이든 참조든 **담은 그릇이 있는 곳**에 함께 있다 — 지역변수면 스택, 객체 필드·배열 칸이면 힙.
> 기본형/참조형을 가르는 기준은 **위치가 아니라 내용(값 자체 vs 참조)**.

- `join()` 이 끝나면 스택 프레임(`count`, `m`)은 사라지지만 힙의 `Member` 객체는 남는다(참조가 없어지면 GC 대상) ([[jvm-stack-and-heap]]).

### 4. 기본형이 존재하는 이유 — 객체 비용

```java
int[]     a = new int[1_000_000];
Integer[] b = new Integer[1_000_000];   // 각 칸에 Integer 객체를 채웠다고 가정
```

| | `int[1_000_000]` | `Integer[1_000_000]` (객체 채움) |
|---|---|---|
| 칸에 들어 있는 것 | 숫자 자체 (4B) | 참조 (압축 참조 시 4B) |
| 추가 비용 | 없음 | 객체 100만 개 × 약 16B (헤더 12B + 값 4B) |
| 대략 총량 | 약 4MB | 약 20MB (64비트 JVM, 압축 참조 기준) |
| 숫자 하나 읽기 | 배열 칸 1번 | 배열 칸 → 참조 따라 객체 → **2번** (캐시 미스 증가) |
| GC | 배열 1개 | 배열 + **객체 100만 개 추적** |

→ 객체 생성·메모리·간접 참조·GC 비용 없이 숫자를 다루기 위해 기본형이 있다.

### 면접 답변

> "기본형은 변수 안에 값 자체가 들어 있고, 참조형은 힙에 있는 객체를 가리키는 참조가 들어 있습니다. 흔히 기본형은 스택에 있다고 하지만, 정확히는 변수를 담은 곳을 따라가서 지역변수면 스택, 객체의 필드면 힙에 있습니다. 기본형이 따로 있는 이유는 숫자 하나하나를 객체로 만들면 객체 헤더와 간접 참조, GC 비용이 들기 때문입니다."

## 오답·헷갈린 점

- **전**: 기본형에 `bit` 포함 9개 → **후**: **8개**. `bit` 는 자바 타입이 아니다.
- **전**: "변수 안에는 기본값 0, 참조형은 null 이 들어 있다" → **후**: 그건 아무것도 넣지 않은 **필드의 기본값**. 질문은 "변수 안에 무엇이 담기나"였다 — 값 자체 vs 참조.
- **전**: "`int` 가 3이면 **미리 만들어 놓은 3을 참조하는 프록시**가 담긴다" → **후**: 기본형 변수엔 **값 자체**. "미리 만든 값 재사용"은 `Integer.valueOf` 캐시(참조형)와의 혼동 — 위키 `wrapper-cache-autoboxing` 오답 "-128~127 은 원시타입의 범위"와 같은 계열.
- **전**: "참조형 변수에는 Member 를 참조하는 **프록시**가 생긴다" (두 번 사용) → **후**: 들어 있는 것은 **참조(reference)**. 프록시는 진짜 객체 대신 호출을 가로채는 **대리 객체**(JPA 지연 로딩, `@Transactional`)로 전혀 다른 개념. 면접에서 바로 지적받는 용어 오용.
- **전**: 지역변수 `x` 를 그냥 출력하면 → "출력을 못 한다" → **후**: 방향 맞음. 정확히는 **컴파일 에러**(런타임에 0/null 이 찍히는 게 아님).
- **전**: "반복적인 생성을 막을 수 있다"(기본형의 존재 이유) → **후**: 방향 맞으나 모호. 객체 헤더 메모리, 간접 참조 2번, GC 추적 비용으로 구체화.
- **전**: `Integer[]` 각 칸이 "숫자가 아니라 null 을 바라본다" → **후**: 객체를 채웠다는 가정이므로 **Integer 객체를 가리키는 참조**.
- **전**: 변수 `m` 은 힙 → **후**: 지역변수라 **스택**. 힙에 있는 건 `m` 이 가리키는 객체. "join() 이 끝나면 m 으로 접근 불가" 반례로 정정.
- 👍 `age`(객체 필드의 기본형)를 처음부터 **힙**이라고 맞힘 — 가장 많이 틀리는 칸.
- `name` 칸에 무엇이 들어 있는지는 두 번 질문했으나 답하지 않음 → 인터뷰어가 정리(String 객체를 가리키는 참조).

## Q&A

**Q. 기본형과 참조형은 무엇이 다른가?**
A. 기본형 변수엔 값 자체, 참조형 변수엔 힙 객체를 가리키는 참조가 들어 있다. 기본형은 null 이 될 수 없다.

**Q. 기본형은 항상 스택에 있나?**
A. 아니다. 지역변수면 스택, 객체 필드·배열 칸이면 힙. 위치는 그릇을 따라간다.

**Q. 초기화하지 않은 지역변수 `int x` 를 출력하면?**
A. 컴파일 에러. 기본값은 필드만 받는다.

**Q. 왜 모든 걸 객체로 만들지 않고 기본형을 두었나?**
A. 객체 헤더 메모리, 참조를 따라가는 간접 접근, GC 추적 비용 때문. `int[100만]` 약 4MB vs `Integer` 객체를 채운 배열 약 20MB.
