## 배운 개념

### 1. 세 존재의 구분 — TV, 리모컨, 설계도

| 비유 | 자바 | 위치 | 개수 |
|---|---|---|---|
| TV 설계도 | 클래스 (`Dog`) | 메서드 영역 | 1개 |
| TV | 인스턴스 (`new Dog()` 의 결과) | 힙 | `new` 실행 횟수만큼 |
| 리모컨 | 참조변수 (`a`, `b`) | 스택(지역변수일 때) | 선언한 만큼 |

> 클래스는 인스턴스의 **설계도이자 타입**이고, 인스턴스는 `new` 로 클래스를 바탕으로 **힙에 생성된 실체**이며, 참조변수는 그 인스턴스의 **참조값을 담아 가리키는** 변수다.

### 2. 클래스의 두 역할

- **타입**: 변수에 무엇을 담을 수 있는지 정한다. `int x` 의 `int` 가 x 의 위치가 아니라 담을 값의 종류를 정하듯, `Dog a` 의 `Dog` 도 a 에 담길 수 있는 것의 종류를 정한다.

```java
int x = 10;
Dog a = new Cat();   // 컴파일 에러 — 타입 불일치 (Cat 이 Dog 의 하위 타입이 아닐 때)
```

- **설계도**: `new` 할 때 어떤 필드와 메서드를 가진 인스턴스를 만들지 정한다. 클래스 정보 자체는 힙이 아니라 메서드 영역에 하나만 있다.

### 3. `new` 두 번 vs 참조 복사

```java
Dog a = new Dog();
Dog b = new Dog();      // new 2번 → 힙에 인스턴스 2개

a.name = "초코";
System.out.println(b.name);  // null — b 는 다른 인스턴스
System.out.println(a == b);  // false — 참조값이 다름
```

```java
Dog a = new Dog();
Dog b = a;              // new 1번 → 인스턴스 1개, 참조값만 복사
                        // a.name 을 바꾸면 b.name 으로도 보인다, a == b 는 true
```

- "같은 곳을 참조한다" 는 말은 **두 번째 경우에만** 맞다.
- 인스턴스 1개 + 변수 2개가 가능하다 → 변수가 곧 인스턴스라면 숫자가 같아야 하므로 둘은 다른 존재다.

### 4. 객체 vs 인스턴스 (용어)

- 실무에서는 섞어 쓴다. "인스턴스" 는 **어떤 클래스의** 실체인지 관계를 강조할 때 자연스럽다 — "a 는 Dog 의 인스턴스다".

## 오답·헷갈린 점

- **전**: 인스턴스란 "class **안에** new 로 생성되어" 힙에 올라가는 것 → **후**: `new Dog()` 가 `Main` 클래스 안에서 실행돼도 만들어지는 건 `Dog` 의 인스턴스. 인스턴스는 클래스 안에 생기는 게 아니라 **클래스를 바탕으로** 힙에 생긴다.
- **전**: `new Dog()` 를 각각 한 `a`, `b` 는 "**같다**. 같은 곳을 참조하는 참조객체이기 때문에" → **후**: `new` 마다 새 인스턴스라 서로 다른 곳을 가리킨다. `a.name = "초코"` 후 `b.name` 은 그대로, `a == b` 는 `false`. 실험 코드로 예측해 보고 스스로 정정.
- **전**: (Q6) "a 는 클래스를 타입으로 생성하는 객체, b 는 실제 클래스가 담겨있는 곳을 참조하는 정보를 담는 것이 인스턴스" → **후**: 참조변수와 인스턴스를 같은 것으로 봤고, 힙에 "클래스가 담겨 있다" 고 봤다. `Dog b = a;` 에서 인스턴스 1개·변수 2개라고 정확히 셌으면서도 "변수 = 인스턴스라고 할 수 있다" 고 결론 → 숫자가 다르면 같은 존재일 수 없다는 모순으로 정정. 힙에는 클래스가 아니라 인스턴스가 있다.
- **전**: `Dog a` 의 `Dog` 는 "a 의 참조객체 위치를 말한다" → **후**: 위치(참조값)는 변수 a 안에 담긴 값이고, `Dog` 는 **타입**이다. `int` 와 비교하고 `Dog a = new Cat()` 컴파일 에러를 보고 스스로 "클래스는 변수의 타입을 지정한다" 로 정정.
- **전**: 클래스 = 메서드·변수를 "묶는 단위" → **후**: 맞지만 절반. 타입 + 설계도까지 말해야 면접 답변이 된다.
- **전**: "저장소에 만든다" → **후**: **힙**. 모호한 단어 대신 메모리 영역 이름으로.

## Q&A

**Q. 클래스와 인스턴스의 관계는?**
A. 클래스는 설계도이자 타입이고, 인스턴스는 `new` 로 그 클래스를 바탕으로 힙에 만든 실체다. 하나의 클래스로 여러 인스턴스를 만들 수 있다.

**Q. `new Dog()` 를 두 번 한 `a`, `b` 에서 `a == b` 는?**
A. `false`. `new` 마다 힙에 새 인스턴스가 생기고 각자 다른 참조값을 받는다.

**Q. `Dog b = new Dog();` 와 `Dog b = a;` 의 차이는?**
A. 앞은 힙에 새 인스턴스를 만들고 그 참조값을 b 에 넣는다. 뒤는 인스턴스를 만들지 않고 a 의 참조값을 복사해 같은 인스턴스를 가리킨다.

**Q. 참조변수와 인스턴스는 같은 것인가?**
A. 아니다. 참조변수는 참조값을 담는 변수(리모컨), 인스턴스는 힙의 실체(TV). `Dog b = a;` 처럼 인스턴스 1개를 변수 여러 개가 가리킬 수 있다.
