## 배운 개념

### 1. 자동 vs 명시 — 기준은 표현 범위

```
byte → short → int → long → float → double
        (char → int)
좁은 → 넓은: 자동 (확대 변환, widening)
넓은 → 좁은: (타입) 필요 (축소 변환, narrowing)
```

```java
int  i = 100;
long l = i;            // (1) ✅ 확대 — 자동
long big = 100L;
int  j = big;          // (2) ❌ 컴파일 에러 — 축소인데 캐스트 없음
int  k = (int) big;    // (3) ✅ 명시적 캐스트
```

- "하위 계층 / 상위 계층"이 아니다. 자바에서 계층은 **상속**을 연상시킨다. 기준은 **표현할 수 있는 범위**.
- `long`(8바이트) → `float`(4바이트)도 **자동**이다. 바이트 크기가 아니라 범위(float 약 ±3.4×10³⁸)가 기준이기 때문.

### 2. 캐스트는 "검사하지 않는 약속"

```java
long big = 3_000_000_000L;   // 30억 (int 범위 밖)
int  k   = (int) big;
System.out.println(k);       // -1294967296  ← 위쪽 32비트를 잘라내고 남은 비트를 int 로 읽음
```

- `(int)` 는 값을 정상으로 바꿔 주는 장치가 아니다. "**잘려도 내가 책임진다**"는 서명.
- 컴파일러도 런타임도 검사하지 않는다 → 약속이 깨지면 에러 없이 **틀린 값**.
- 검사하는 버전이 필요하면 `Math.toIntExact` ([[2026-10-22-integer-overflow-wraparound]]).

### 3. 연산 타입은 피연산자가 정한다 — 산술 승격

**(a) long 에 담아도 넘친다**

```java
long total = 50_000 * 50_000;
System.out.println(total);   // -1794967296
```

```
① 50_000 * 50_000     int × int → int. 25억은 int 에 안 들어감 → 여기서 이미 넘침
② total = (그 int 값)  int → long 확대. 손실 없이 깨진 값을 그대로 넓힘
```

- 잘림은 **① 곱셈 안에서** 일어난다. ② 확대 변환은 절대 값을 잃지 않는다.

| 코드 | 결과 | 이유 |
|---|---|---|
| `long a = (long) (50_000 * 50_000);` | -1794967296 | 캐스트가 곱셈 **뒤**. 괄호 안 int 곱셈이 먼저 넘침 |
| `long b = (long) 50_000 * 50_000;` | 2500000000 | 캐스트가 `*` 보다 먼저 결합 → 첫 피연산자가 long → long 곱셈 |
| `long c = 50_000L * 50_000;` | 2500000000 | long 리터럴 → long 곱셈 |

> **결과를 담을 변수의 타입이 아니라, 연산 순간 피연산자의 타입이 연산 타입을 정한다.**

**(b) 작은 타입끼리 더했는데 컴파일 에러**

```java
byte a = 10;
byte b = 20;
byte c = a + b;      // ❌ 컴파일 에러
```

```
byte + byte → (연산 전에) int + int → 결과 int → byte 로 축소 → 캐스트 없으니 에러
```

- `int` 보다 작은 타입(`byte`, `short`, `char`)은 연산 **전에** `int` 로 승격된다(산술 승격, numeric promotion).
- 컴파일러가 막는 근거는 **값이 아니라 타입**. `a`, `b` 는 변수라 실행 중 120 + 120 이 올 수도 있다.

```java
byte c1 = 10 + 20;   // ✅ 상수 표현식 — 컴파일러가 값(30)을 알고 byte 범위 안이라 허용

byte c2 = 120;
c2 += 10;            // ✅ 컴파일됨 — c2 = (byte)(c2 + 10) 의 숨은 캐스트
System.out.println(c2);   // -126  ← 경고 없이 조용히 감겨 돎
```

- `+=` 는 편하지만 **명시적 캐스트를 숨긴 것**이라 오버플로를 눈에서 가린다.

### 4. 확대 변환도 정밀도는 잃을 수 있다

```java
int   big = 16_777_217;
float f   = big;              // 캐스트 없이 자동 (확대 변환)
System.out.println((int) f);  // 16777216  ← 1이 사라짐
```

```
float (32비트) = 부호 1비트 + 지수 8비트 + 유효숫자 23비트(+ 숨은 1비트 = 24비트 정밀도)
```

- 지수에 비트를 써서 **범위**를 얻고, 유효숫자는 24비트뿐이라 **정밀도**를 잃는다. 2²⁴ = 16,777,216 까지만 모든 정수를 정확히 표현.
- `16_777_217` 은 25비트가 필요 → 가장 가까운 값으로 반올림.
- 확대 변환은 **범위** 손실은 없지만 `int`/`long` → `float`/`double` 은 **정밀도** 손실이 가능하다(그런데도 자동 허용). `long` → `double` 은 2⁵³ 초과 시.
- `0.1 + 0.2 == 0.30000000000000004` 도 같은 원리(0.1 이 이진수로 딱 떨어지지 않음) → **금액은 `double` 금지**, `long`(원 단위)이나 `BigDecimal`.

### 면접 답변

> "표현 범위가 좁은 타입에서 넓은 타입으로는 자동으로 변환되고, 반대는 명시적 캐스트가 필요합니다. 캐스트는 위쪽 비트를 그냥 잘라내기 때문에 값이 바뀌어도 에러가 나지 않습니다. 또 연산 타입은 결과를 담을 변수가 아니라 피연산자가 정해서, long 변수에 int 끼리의 곱을 담으면 곱셈 단계에서 이미 넘칩니다. 그리고 int 나 long 을 float, double 로 바꾸는 건 자동이지만 정밀도를 잃을 수 있어서 금액 계산에는 BigDecimal 을 씁니다."

## 오답·헷갈린 점

- 👍 (2) `int j = big` 이 컴파일 안 되는 줄 — 정답.
- **전**: "하위 계층이 상위 계층으로 가는 것은 자동" → **후**: "계층"은 상속을 연상시킨다. 기준은 **표현 범위**(좁은 → 넓은).
- **전**: "직접 캐스팅을 해줘야 **정상적으로** 진행된다" → **후**: 캐스트는 값을 고쳐 주지 않는다. `(int) 3_000_000_000L == -1294967296`.
- **전**: 캐스트 = "이 값은 해당 타입을 넘지 않는다는 약속" → **후**: 방향 맞음. 단 그 약속을 **아무도 검사하지 않는다** — 깨지면 조용히 틀린 값.
- **전**: `long total = 50_000 * 50_000` 은 "total 에 **담길 때** 자동 캐스트되며 int 범위를 넘어 잘린다" → **후**: 잘림은 **int 곱셈 안에서**. int → long 확대는 값을 잃지 않는다. "담길 때 잘린다"로 이해하면 `(long)(a * b)` 같은 틀린 수정을 하게 됨.
- **전**: B·C 가 되는 이유 = "long 타입으로 명시해줬기 때문" → **후**: A 도 명시했지만 실패. 이유는 **곱하기 전에** 피연산자가 long 이 되었느냐(캐스트는 `*` 보다 먼저 결합).
- **전**: `byte c = a + b` 에러 = "연산이 먼저 진행되고 값 변환이 일어나기 때문" → **후**: **산술 승격** — 연산 전에 int 로 올라가고, int → byte 축소를 컴파일러가 막는다. 컴파일러는 값을 모른다.
- 👍 `c2 += a` 의 숨은 `(byte)` 캐스트를 찾음. (`byte c1 = 10 + 20` 상수 표현식 케이스는 답하지 않아 보충받음)
- **전**: float 정밀도 손실 원인 = "소수 경우의 수?" → **후**: 32비트를 지수·유효숫자로 나눠 **범위를 얻고 정밀도를 잃음**(24비트).
- ⚠️ 반복 테마: 결과·방향은 맞히는데 **"언제/어디서" 일어나는지**(잘림 시점, 캐스트 결합 대상, 컴파일러의 판단 근거)를 뭉뚱그림. 오늘 클래스 로딩·언박싱 NPE 인터뷰의 "컴파일 시점 vs 실행 시점" 혼동과 같은 계열.

## Q&A

**Q. 묵시적 형변환과 명시적 형변환의 규칙은?**
A. 표현 범위가 좁은 → 넓은 타입은 자동(확대), 넓은 → 좁은은 `(타입)` 필요(축소). 축소는 위쪽 비트를 잘라낸다.

**Q. `(int) 3_000_000_000L` 은?**
A. -1294967296. 캐스트는 검사하지 않는 약속.

**Q. `long total = 50_000 * 50_000` 이 왜 음수인가? 어떻게 고치나?**
A. int × int 곱셈에서 이미 넘친다. `50_000L * 50_000` 또는 `(long) 50_000 * 50_000` 처럼 곱하기 **전에** long 으로 만든다. `(long)(50_000 * 50_000)` 은 안 된다.

**Q. `byte c = a + b` 는 왜 컴파일 에러인데 `byte c = 10 + 20` 과 `c += a` 는 되나?**
A. 산술 승격으로 결과가 int. 리터럴끼리는 상수 표현식이라 컴파일러가 값을 알아 허용, `+=` 는 숨은 `(byte)` 캐스트 포함.

**Q. 확대 변환은 항상 안전한가?**
A. 범위는 안전하지만 int/long → float/double 은 정밀도를 잃을 수 있다(`16_777_217` → `16_777_216`).
