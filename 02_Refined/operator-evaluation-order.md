# 연산자 평가 순서의 함정

## 개념 정의

자바는 피연산자를 **왼쪽부터** 평가하고, 같은 우선순위의 `+` 는 **왼쪽부터** 결합한다. 같은 기호라도 이 순서에 따라 결과가 달라진다.

## 작동 원리

### 후위 증가 — `i = i++` 는 5

```java
int i = 5;
i = i++;
System.out.println(i);   // 5
```

```
① i++ 가 지금 값 5 를 임시로 꺼내 둔다
② i 를 6 으로 올린다            ← +1 은 여기서 이미 끝남
③ i = (꺼내 둔 5)              ← 대입이 6 을 5 로 덮어씀
```

"먼저 값을 돌려주고 나중에 +1" 이라고만 기억하면 최종 값이 6 이어야 할 것 같다. 핵심은 **+1 이 대입보다 먼저 끝나고, 대입이 그것을 덮어쓴다**는 순서다.

### 문자열 연결 — 왼쪽부터, String 을 만나는 순간부터

```java
System.out.println(1 + 2 + "3");   // "33"   : (1 + 2) = 3 → 3 + "3"
System.out.println("1" + 2 + 3);   // "123"  : "1" + 2 = "12" → "12" + 3
```

`+` 의 피연산자 중 하나라도 String 이면 그 `+` 는 덧셈이 아니라 **연결**이다. 연결의 성능 비용은 [[string-concatenation-cost]].

## 트레이드오프 / 한계

- 같은 변수를 한 문장에서 증가시키고 대입까지 하면 착시가 생긴다 → `i++` 는 **단독 문장**으로만 쓴다.
- 로그 문자열에 계산을 섞을 때(`"합계: " + a + b`) 의도와 다르게 연결된다 → 계산은 괄호로 묶는다: `"합계: " + (a + b)`.
- 조건식 안의 부수 효과도 같은 계열의 위험이다 ([[short-circuit-evaluation]]).

> [!WARNING]
> **오답 코너**
> - **"`i++` 는 값을 돌려주고 나중에 +1 하니까 `i = i++` 후 i 는 6"** — +1 은 대입보다 **먼저** 끝나고, 대입이 꺼내 둔 5 로 덮어쓴다 → **5**.

## 면접 답변

> "i = i++ 는 i++ 가 현재 값 5 를 먼저 꺼내 두고 i 를 6 으로 올린 다음, 대입이 꺼내 둔 5 로 다시 덮어쓰기 때문에 5 가 됩니다. 문자열 연결은 왼쪽부터 계산되기 때문에 1 + 2 + "3" 은 3 에 "3" 을 붙여 "33" 이 되고, "1" + 2 + 3 은 처음부터 연결이라 "123" 이 됩니다."
